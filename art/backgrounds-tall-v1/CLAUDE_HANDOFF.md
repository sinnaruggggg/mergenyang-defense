# 긴 배경 4종 — 제작 및 연결 인계

## 현재 상태

2026-09-18 built-in image_gen 편집으로 기존 배경을 참조한 세로 확장 PNG 4종을 제작했다. 천장·하늘·바닥이 실제 그림으로 추가되어 있으며, 거울 띠/가장자리 늘이기/블러 연장은 사용하지 않았다. 원본은 보존했다.

**v0.2.3 작업에서 사용자의 승인으로 native 배경과 Gfx 렌더러에 연결했다.** 가장자리 반복·늘이기를 제거했다. FTP용 웹 실행본은 이번 Android 릴리스 작업 대상이 아니다. 아래 연결 방법은 최초 전달 시 작성한 지침이며 현재 구현은 native 코드를 기준으로 한다.

| PNG | 실제 크기 | 사용 메뉴 |
| --- | --- | --- |
| workshop.png | 821 × 1915 | 로비(lobby-room), 타이틀, 대장간/머지냥이 성장 |
| town.png | 821 × 1915 | 고양이, 모드 선택, 스테이지, 랭킹 |
| shop.png | 821 × 1915 | 상점 |
| battle.png | 822 × 1914 | 전투 |

목표는 9:21. 도구 출력은 위 표의 크기로 반환됐다. 1080×2520 제작 요청과 실제 해상도를 혼동하지 말 것. 픽셀을 억지로 1080×2520에 맞추지 않고 원본 비율을 사용한다.

## 검수 및 제한

- 4종을 직접 열어 확인했다. 그림의 연결과 원근은 자연스럽고 UI·문자·캐릭터가 추가되지 않았다.
- 원본 중앙을 보존하도록 요청했지만 AI가 전체 이미지를 재생성하므로 중앙 영역은 픽셀 단위 동일하지 않다. 원본 그대로라는 보장은 하지 않는다.
- 특히 battle의 전장 바닥과 나무 영역 경계는 원본과 다소 달라졌다. 기존 GROUND/레일/보드와 실제 렌더링 비교가 필요하다. 확인 없이 배포하지 말 것.
- preview.html에서 원본/전체/기기별 크롭을 비교할 수 있다. PNG 에셋만 전송하면 preview의 기존 배경 비교 경로는 작동하지 않으므로 원본 프로젝트 안에서 열 것.

## 네이티브 연결 방법

1. native/assets/backgrounds에 별도 이름(workshop-tall, town-tall, shop-tall, battle-tall)으로 복사하고 Assets.kt 로드 목록에 추가한다. 기존 PNG를 삭제할 필요는 없다.
2. Gfx.background()의 3.5% 상하 띠 추출·뒤집기·늘이기와 shadeTexture 음영 감추기 처리를 제거한다.
3. 긴 PNG를 폭 기준으로 균등 배율로 그린다. 예: `scale = 1080 / regionWidth`, `drawHeight = regionHeight * scale`, `x = 0`, `topY = (1920 - drawHeight) / 2`. 기존 좌상단 좌표 도우미 기준이다.
4. 9:16은 중앙 영역만 보이고 긴 기기는 같은 배율에서 위아래가 더 보이게 한다. 화면 높이에 맞춰 Y축만 늘리면 안 된다. 가로와 세로에 같은 scale을 적용한다.
5. 로비도 Gfx.cover() 확대 대신 같은 긴 배경 그리기 경로를 쓴다. 불티를 Gfx.coverX/Y로 확대 변환하던 부분은 배경에 맞춰 다시 확인한다.
6. 버튼/캐릭터 크기와 보드 셀 크기는 그대로 유지한다. anchorTop/anchorBottom과 safe area는 유지한다.
7. 9:21보다 긴 기기에서는 이미지 높이가 부족할 수 있다. 필요하면 장변을 더 확장한 그림을 제작해야 한다. 임의의 늘이기나 거울 반복으로 되돌리지 말 것.

## 빌드 후 확인

- 9:16, 9:19.5, 9:20, 9:21 화면에서 위아래 여백 및 이음새 확인.
- 로비 허리 단면이 보상 박스 뒤에 가려지는지 확인.
- 상점 상인의 위치와 카운터 정합 확인.
- 전투의 발 접지, 레일, 보드 프레임 정합을 우선 확인. 배경 차이를 숨기려고 보드/캐릭터를 비균등 확대하지 말 것.
- 다른 메뉴 UI 디자인은 변경하지 않는다.
